NodeNorm Canonicalization

NodeNorm validation status for each harmonized node. It helps identify cases where a preferred CURIE is available, matches the local source standard, or remains unresolved.

Evidence Layers

Relationship rows exported for the graph. Identity xrefs are merge evidence. External identifiers, PubMed references, RxNorm products, and target interactions are retained as context layers.

Primary Identity Key

Primary key type used to seed or preserve a harmonized drug component before NodeNorm canonicalization. InChIKey and source identifiers are used carefully because salts, mixtures, isomers, and products can collapse incorrectly if treated as interchangeable.

Biolink Category Distribution

Concept-level Biolink category assigned during drug harmonization. The dashboard separates curated drug-like nodes from broader chemical entities.

Source Update Status

Download/transform status from the latest ODIN run. xref_only means identifiers are retained from other source xrefs without ingesting the full optional dataset. disabled means the source layer is intentionally not run in this release.

Resolver Tab

The resolver searches the harmonized drug graph first, then optionally enriches candidates with NCATS Resolver, Pharos targets, Inxight/GSRS, openFDA labels, and ChEBI class context. It is a candidate-ranking workflow, not a silent authority for new mappings.

Drug Harmonizer API

GET/drug-id-qa/api/stats
Release stats, source coverage, identity-key tiers, relationship counts, and source catalog.
GET/drug-id-qa/api/search?q=aspirin
Search IFXDrug IDs, names, synonyms, UNII, ChEMBL, ChEBI, PubChem CID, DrugCentral, RxCUI, CAS, and InChIKey.
GET/drug-id-qa/api/graph?ids=aspirin
Graph-ready identity xrefs, product context, and drug-target evidence.
GET/drug-id-qa/api/ncats-properties
NCATS Resolver property catalog — all queryable properties with display names, categories, and defaults.
POST/drug-id-qa/api/resolve
Batch resolve + enrich drug queries against local graph and live APIs (NCATS Resolver, Pharos, Inxight, openFDA, ChEBI). Accepts optional ncats_props array to select NCATS properties.
POST/drug-id-qa/api/resolve-job
Start a larger resolve + enrich job with pollable progress.
GET/drug-id-qa/api/resolve-job/{job_id}
Poll a resolver job for completed row count, source hit counts, errors, and final result payload.
POST/drug-id-qa/api/resolve
Quick local-only resolution uses the same batch endpoint with enrichment disabled. This avoids long browser URLs for pasted drug lists.

Drug Resolver

Resolve against the ODIN/IFX harmonized graph, then annotate from selected live APIs

Local harmonizer

Resolves names and identifiers to IFXDrug IDs curated from GSRS/UNII, ChEMBL, ChEBI, DrugCentral, PubChem CIDs, RxNorm context, and NodeNorm validation.

NCATS / IFX enrichment

NCATS Resolver adds structure and identifier properties. Pharos adds targets, MOA, TDL, and target-family context. Inxight/GSRS adds registry, regulatory, class, and relationship annotations.

External annotation

openFDA adds label/manufacturer/route/warning context. ChEBI OLS adds ontology label, definition, and chemical-class hierarchy.
